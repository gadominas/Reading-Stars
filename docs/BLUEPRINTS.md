## Recipes

Coding rules every app follows (https://github.com/gadominas/app-blueprints/tree/main/recipes). They describe how the code is written, not a feature, so they aren't listed in the script's `BLUEPRINTS` block or in Built with.

| Recipe | Version | Since app version | Deviations |
| --- | --- | --- | --- |
| [safe-startup](https://github.com/gadominas/app-blueprints/blob/safe-startup-v1.1.0/recipes/safe-startup.md) | 1.1.0 | 1.5.0 | Data files: `data` (players, tokens, budgets, PIN hash, language, book words, word progress) and its backup; AI token counts (`reading-stars-usage.json`) are a local file read in `loadData()` and never saved before they were read. When data.json is on the phone but missing, unreadable or damaged (not just late from iCloud), `loadData()` reads `data.backup.json` instead, as the app did before, and saving goes on; a file that is only late is never replaced. A damaged data.json is always copied aside first (`data.broken-<time>.json`); if the backup restores the game, no toast is shown (only a start-up log line); if the backup is damaged too (or missing), the game starts fresh, says so in the game's language, and saves again. No `write()`/`saveAll()`: the page sends its whole state through the `save` bridge, so the guard sits in `saveData()` (data.json and its backup) and `saveSettings()`, and the save on close still goes through `window.__flush` (1.5 s limit). The list handed over in pieces is `kids`, 6 at a time; `webApp` reads `window.__INITIAL__` (the app's existing name), so `__boot` sets that instead of `__INIT`. No refresh of its own, so no 0.7 s timer; the widget icon moved from the start to 6 s. The placeholder (`Loading your players…`), the stall note, the iCloud toast and the started-fresh toast follow the game's language (Lithuanian, English, Spanish), read from the widget snapshot before data.json is read, as the launch screen's tagline now is; the placeholder sits on a `--sheet` card because the page's ground is the sky backdrop. Settings › Updates › Start-up log is behind the parent PIN like the rest of Settings, and its labels follow the game's language. The widget branch calls `loadData()` but still draws from its snapshot (names, avatars, points, tokens, language). The start-up log holds counts, timings and file names only: never money, budgets, payouts or the PIN. The Scriptable-side `toast()` uses the page's `window.__toast`, and every page message (`js()`) goes through `ev()` |

## Not from a blueprint

**Read words aloud** (1.8.0) speaks one word, not a text, so it does not follow the `read-aloud` blueprint (player, sentence highlighting, text view). It reuses that blueprint's rules for voices: the iPhone's voices through Web Speech, speech started from a tap where possible (the play tap, the right answer, the 🔊 button), and Scriptable's `Speech` as the fallback.

**Words from books, smart word order and the AI coach** (1.8.0) are this app's own features. Their AI requests go through `aiCall` like every other AI request.
