## Recipes

Coding rules every app follows (https://github.com/gadominas/app-blueprints/tree/main/recipes). They describe how the code is written, not a feature, so they aren't listed in the script's `BLUEPRINTS` block or in Built with.

| Recipe | Version | Since app version | Deviations |
| --- | --- | --- | --- |
| [safe-startup](https://github.com/gadominas/app-blueprints/blob/safe-startup-v1.0.0/recipes/safe-startup.md) | 1.0.0 | 1.5.0 | Data files: `data` (players, tokens, budgets, PIN hash, language) and its backup. When data.json is on the phone but missing or broken (not just late from iCloud), `loadData()` reads `data.backup.json` instead, as the app did before, and saving goes on; a file that is only late is never replaced. No `write()`/`saveAll()`: the page sends its whole state through the `save` bridge, so the guard sits in `saveData()` (data.json and its backup) and `saveSettings()`, and the save on close still goes through `window.__flush` (1.5 s limit). The list handed over in pieces is `kids`, 6 at a time; `webApp` reads `window.__INITIAL__` (the app's existing name), so `__boot` sets that instead of `__INIT`. No refresh of its own, so no 0.7 s timer; the widget icon moved from the start to 6 s. The placeholder (`Loading your players…`), the stall note and the iCloud toast follow the game's language (Lithuanian, English, Spanish), read from the widget snapshot before data.json is read, as the launch screen's tagline now is; the placeholder sits on a `--sheet` card because the page's ground is the sky backdrop. Settings › Updates › Start-up log is behind the parent PIN like the rest of Settings, and its labels follow the game's language. The widget branch calls `loadData()` but still draws from its snapshot (names, avatars, points, tokens, language). The start-up log holds counts, timings and file names only: never money, budgets, payouts or the PIN. The Scriptable-side `toast()` uses the page's `window.__toast`, and every page message (`js()`) goes through `ev()` |
